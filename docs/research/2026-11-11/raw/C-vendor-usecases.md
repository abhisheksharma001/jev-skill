Research date: 2026-11-11 (IST). Source: TypeSafe's own docs, blog, and demo pages. Every number here is the vendor's claim unless marked otherwise. Nothing was independently re-run.

## How this was read

- Live reads: the docs index (https://docs.typesafe.ai/llms.txt) and every page in it were fetched live on 2026-11-11 with Keenable (`live: true`). Raw re-checks used TinyFish (`ttl: 0`) on the same URLs. Version strings and headline numbers were confirmed against the raw text where noted.
- Version drift: several pages changed between the search-index copies (acquired 2026-10-13 to 2026-11-09) and the live copies read on 2026-11-11. Where the two disagree, both are reported. The live copy is treated as current.
- Pages read in full: 27 cookbooks, 2 demos, the use-case map, 6 pattern pages, the changelog, the model-jaggedness page, the blog index, and 9 blog posts (8 from the index plus the Jack & Jill case study). The Jev models page was read only through a search snippet (index copy acquired 2026-11-11). Two blog posts could not be extracted (see section 4).

## 2. Use-case map (https://docs.typesafe.ai/concepts/use-case-map)

Read live 2026-11-11 (Keenable, raw markdown). Source page is dated 2026-11-04 in the index. The page lists 5 headline categories and 19 industry areas.

Headline categories:
- AI Automation Software: code owns control flow; Jev handles semantic decisions.
- Real-time applications: "frontier intelligence at real-time speeds (150ms)". Vendor claim, no n.
- AI Map Reduce over Big Data: "100x cheaper" for large datasets. Vendor claim, no n.
- Universal Verification: check inputs, extractions, reasoning traces, tool calls and outputs of other AIs.
- Harness Engineering: model routing, retrieval, guardrails, trace classification.

Industry and use-case areas:
1. Search and retrieval: semantic search, scoring, pairwise rerank, cross-encoding, context selection.
2. Scientific discovery: screen papers for systematic reviews, label transcripts and survey responses, check citations, flag missing methods, build knowledge graphs.
3. Model routing: custom router choosing which LLM gets each prompt; classify intent and domain; estimate difficulty and risk; escalate.
4. LLM guardrails: checks on every input, output and tool call; jailbreaks and prompt injection; policy violations; sensitive-data exposure; tool-call errors.
5. Semantic code linting: team-specific checks run in CI.
6. Feature extraction for predictive modeling: probabilistic features combined with structured data; autoresearch to propose features.
7. Recruiting: score resumes and feedback against job criteria; match candidates; escalate uncertain cases.
8. Lead generation: ICP fit, company maturity, buyer intent, lead routing.
9. Customer support: ticket classification, transcript issue extraction, urgency and churn, routing, policy verification.
10. Insurance claims: classify first notices of loss; complexity and fraud indicators; straight-through vs specialist review.
11. Financial crime: transaction narratives and KYC; entity matching; alert prioritisation; investigator routing.
12. Legal and compliance: classify contracts and claims; missing clauses; verify against requirements; escalate to counsel.
13. E-commerce marketplaces: normalise listings; extract attributes; detect prohibited or counterfeit listings and review abuse; rank.
14. Moderation and trust and safety: company-specific criteria; toxicity, harassment, spam, fraud, unsafe advice, personal data; allow / warn / review / block.
15. Advertising: brand safety; audience suitability; prohibited claims; ad-to-landing-page alignment.
16. Gaming: chat moderation; abuse and suspicious behaviour; frustration and engagement; churn signals.
17. Risk assessment: incident and claims notes to risk indicators; severity scoring; feature extraction for risk models.
18. Demand forecasting: semantic signals from inquiries, reviews, tickets and market reports fed into forecasting models.
19. Graphs and knowledge graphs: annotate and verify graphs; relationship and entity types; contradictions; hierarchical classification.

Task categories (table on the same page): Classification, Detection, Scoring, Routing, Search, Retrieval, Ranking, Verification, ML Feature Extraction, Structured Data Extraction.

## 3. Pattern summary (recommended thresholds)

Read live 2026-11-11 and raw-checked. None of the six pattern pages states a measured accuracy, n or baseline.

- Speculative fan-out (https://docs.typesafe.ai/patterns/fan-out): put every question in one request and let code filter. Example thresholds: bug_severity.score > 1.5; bug_repro.noul > 0.6; refund.noul > 0.7; frustration.score > 1.5. No measured numbers.
- Screen with a Noul first (https://docs.typesafe.ai/patterns/noul-screen): YES_ABOVE = 0.7, NO_BELOW = 0.3; the band between gets its own outcome. Model named: jev-1.14.0.
- Companion Noul (https://docs.typesafe.ai/patterns/companion-noul): YES = 0.7, NO = 0.3; trust the Choice only when Noul > 0.7 and Choice probability > 0.7 (PRODUCT_SURE). Noul < 0.3 means ignore the Choice. Model: jev-1.14.0.
- Routing by confidence (https://docs.typesafe.ai/patterns/confidence-routing): confidence < 0.5 goes to a person. Score bands: < 1.5 backlog, 1.5 to < 2.5 sprint, >= 2.5 on-call. Blocked = P(level 3) + P(level 4) >= 0.3 triggers on-call. Gotcha: two adjacent top levels can pass a confidence check while straddling a threshold. Model: jev-1.14.0.
- Routing by probability (https://docs.typesafe.ai/patterns/probability-routing): below 0.7 goes to a support agent; check_balance at >= 0.7; approve_transfer at 0.7 to 0.9 asks to clarify; above 0.9 shows a confirmation screen. Thresholds choose a workflow only and never move money. Confidence is not used for Choice (it is derived from the top probability). Model: jev-1.14.0.
- Composite scoring (https://docs.typesafe.ai/patterns/composite-scoring): divide each Score by 4, then weight in code. Example weights: Senior IC 40% Python / 10% leadership / 40% design / 10% generalist; Engineering Manager 15% / 40% / 20% / 25%. No model or measured numbers stated.
